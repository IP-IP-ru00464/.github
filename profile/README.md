<h2>测试分三个时点，不是测一次就完事</h2>
<p>家宽 IP 的表现会随时间变化，所以单次测试的结论意义有限。真正有用的做法是在三个时点各测一遍：刚拿到手时测基线，连续七天测稳定性，更换或续费后再复测一次。三个时点的数据放在一起，才能判断这条线路是不是能用。</p>
<p>刚到手的测试解决「是不是货不对板」，连测七天解决「会不会间歇性出问题」，换线后复测解决「换来的这条是不是同一水平」。跳过任何一个，后面都可能踩坑。</p>

<h2>刚到手测什么：先看身份，再看速度</h2>
<p>顺序不能反。很多人一上手就跑测速，速度好看就放心了，结果地址类型是机房，白高兴一场。正确顺序是先确认身份：地址归属地、地址类型、运营商标识、是否在公开黑名单里。</p>
<p>身份没问题再看速度。速度测试要挑自己的业务时段做，用自己真实会用的操作去测，而不是只看一个跑分数字。测速网站的数字和实际传文件、开页面的感受经常差别很大。</p>

<h2>连续七天测什么：抖动、掉线、地址变化</h2>
<p>这七天要盯三个值：延迟的波动范围、有没有掉线、出口地址有没有变。延迟均值好看但波动大，用起来照样难受；偶发掉线在测试时容易漏掉，只有连续观察才能发现规律。</p>
<p>建议每天固定两个时段各记一次，其中一次放在当地晚高峰。晚高峰是家宽线路压力最大的时候，也是问题最集中暴露的时候。如果晚高峰表现和平时差不多，这条线路的质量基本可以放心。</p>

<h2>地址类型这一项，为什么要交叉核对</h2>
<p>因为不同数据库的判定标准不一样。同一个地址，有的库标为住宅，有的库标为商业，还有的库干脆没有记录。只看一家，很可能得到一个偏乐观或偏悲观的结论。</p>
<p>建议至少查三家，取多数结论。如果三家分歧很大，说明这条地址的归属信息本身不清晰，这种「模糊地址」在实际使用中风险偏高，宁可换一条清晰的。</p>

<h2>测速度的正确方法</h2>
<p>别用通用测速网站的结果下结论，它测的是到测速节点的速度，不是到你目标站点的速度。正确做法是拿目标站点的实际操作来计时：打开首页多久、提交一次表单多久、上传一个文件多久。</p>
<p>同时要分清是「线路慢」还是「目标站点慢」。判断方法是用同一台设备、同一时间，直连和走线路各测一次，对比差值。差值才是线路带来的额外开销。</p>

<h2>更换或续费之后必须复测</h2>
<p>这是最容易被省掉的一步。很多人换了一条新线路，凭「同一家服务商，应该一样」就直接投入使用，结果新线路的地址段被污染过、或者上行档位更低。</p>
<p>复测不需要七天，把身份和速度两项跑一遍就够。花十分钟，能避免用一周之后才发现问题、再折腾一轮迁移的麻烦。</p>

<h2>把测试结果留下来</h2>
<p>每次测试都记下日期、线路编号、六项数值和结论。积累三五条之后，你手里就有了一份自己的资源质量档案。这份档案在续费议价、换供应商、排查故障时都能直接用上，比凭印象判断可靠得多。</p>
<p>记录不需要多精细，一张表、几列数字就够。关键是坚持记，而不是测完就忘。</p>

<h2>常见问答</h2>
<h3>测速网站的分数高就说明线路好吗？</h3>
<p><strong>答：</strong>不一定。分数反映的是到特定节点的带宽，不反映稳定性、地址类型和实际业务体验。三项要分开看。</p>
<h3>晚高峰一定要测吗？</h3>
<p><strong>答：</strong>建议测。家宽线路的短板基本都在晚高峰暴露，只看白天的数据容易得出过于乐观的结论。</p>
<h3>延迟多少算合格？</h3>
<p><strong>答：</strong>取决于业务。一般网页操作能接受较高延迟，实时交互要求更严。更该关注的是波动，而不是绝对数值。</p>
<h3>地址被标成商业类型还能用吗？</h3>
<p><strong>答：</strong>技术上能用，但网络特征与家庭用户不符，是否合适取决于具体用途。对网络身份一致性有要求的场景，建议换一条标记清晰的。</p>
